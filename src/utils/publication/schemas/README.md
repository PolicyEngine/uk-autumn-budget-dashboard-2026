# Execution-plan wire evidence

The browser validates ordered execution plans and recomputes their identities from JSON. It treats carried module and function names as text. Runtime workers separately bind trusted functions, and publication retains its approval and data gates.

PolicyEngine's generators produce these schemas and vectors from the committed source in [source-provenance.json](./source-provenance.json), which records its revision and file hashes. Regenerate from that source and copy exact bytes, including the expected identities.

The ordered fixture uses a wheel built from the recorded commit. Its declared version, 6.17.2, does not identify the PyPI 6.17.2 artifact.

The browser checks the actual model identity before choosing a historical reader. Its native comparison contract applies from the dashboard's migration floor, UK 2.174.1, onward. That threshold records the dashboard's receipt migration and does not date the model's policy content. The browser compares version epochs and release tuples, treating pre-release, development and local builds in the same release cohort as native. It requires each comparison with shared native parameters to match the model version in the trusted policy record.

The browser rejects integral JavaScript Numbers outside the safe-integer range. Parsed JSON cannot distinguish an unsafe Python integer from a finite Python float with the same mathematical value. This consumer supports a narrower numeric domain than the Python API.
