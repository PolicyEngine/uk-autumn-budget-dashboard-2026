It could also show the fiscal events PolicyEngine has already replayed: the Spring Budget 2023, the Autumn Statement 2023, the Spring Budget 2024, the Autumn Budget 2024, the Spring Statement 2025 and the Autumn Budget 2025. This dashboard reruns those constructions on its own certified pair.

## What a historical figure means

Every historical figure is costed on **today's** certified model and data: the pair this dashboard runs, which on 24 October is policyengine 6.10.2, policyengine-uk 2.132.6 and Microcosm UK 2024-25. The figures are not the estimates made at the time. Each measure is costed at the margin of today's law:

- **A measure still in law** is a *reversal*. The baseline undoes the measure, and the reform is current law. The figure is what the measure is worth today.
- **A measure no longer in law, or never commenced,** is a *forward delta*. The baseline is current law, and the reform adds the measure.

So a measure that a later event changed is costed with that later change still in place. For example, the Autumn Budget 2024 winter fuel means test is reversed by switching off only its benefit condition, leaving the Autumn Budget 2025's income test as today's law has it. Likewise, the 2p Class 1 employee NICs cuts in the Autumn Statement 2023 and the Spring Budget 2024 each reverse 8% to 10% on today's law, so they cost the same.

Years are fiscal years, with year Y read as Y-(Y+1), as on the 2026 page, from 2026-27 (question 7). Signs are the Exchequer's: positive improves the public finances.

A page shows four things:
- **The pair.** The model and data pair, read from the release's manifest (`execution.identity`), in a banner that says the figures are on today's model and data, not what was known at the time.
- **Coverage.** The event's coverage in the scorecard's accounting. Of everything the OBR costed (measures, and the absolute £ across its source rows and years), how much PolicyEngine models, how much is partial, how much it cannot yet express (and whether the gap is in the construction or in the model or data), and how much is outside a household model.
- **Measures not modelled.** Every measure not modelled is still listed, with its class and the scorecard's reason.
- **The OBR comparison.** For each modelled measure in the selected year: the OBR's costing over all its heads, its costing over only the heads the replay models, this page's figure, and the scorecard replay's figure on the scorecard's own pair (named in `obr_comparison.csv`'s `replay_pair`). It is shown for context, and does not gate a figure.

Each page links to [the scorecard](https://policyengine-scorecard.vercel.app/scorecard/?country=uk&view=validation) for the replay itself rather than repeating it. It shows national aggregates only: no figure from a single household record is ever published.

## Design

### The release is a dimension

`src/uk_budget_data/releases.json` lists every release the dashboard can serve, and nothing else is served. Python reads it in `uk_budget_data/releases.py`, which validates it, and the page in `src/utils/publication/release.js`.

```json
{
  "schema": "uk-budget-dashboard/releases/v1",
  "default": "uk-autumn-budget-2026",
  "releases": [
    {"id": "uk-autumn-budget-2026", "kind": "current", "name": "Autumn Budget 2026",
     "date": "2026-10-28", "data_root": ""},
    {"id": "uk-autumn-budget-2024", "kind": "historical", "name": "Autumn Budget 2024",
     "date": "2024-10-30", "data_root": "releases/uk-autumn-budget-2024",
     "event": "autumn_budget_2024"}
  ]
}
```

- **Identity.** A release's identity is its `id`, `name` and `date`. A manifest authorises figures only for the release whose root it was read from, and only when `manifest.release` is that release's id and `manifest.budget` its id and date. `assertCurrentRelease` stays, as `assertRelease(manifest, DEFAULT_RELEASE)`, with its message, so every 2026 check is unchanged.
- **Data root.** The 2026 release keeps `public/data`, and every 2026 path is unchanged. A historical release has its own root: `public/data/releases/<id>/` holds its manifest, artifacts, release index and flat views. **The root decides the release.** A data root directly inside a `releases` directory serves the registered historical release of that name; one that names no registered release is refused, never read as this Budget; any other root serves this Budget (`releases.release_for_root`). No manifest entry's artifact path may enter `releases/`, in Python (`manifest.Entry`) or on the page (`isSafeArtifactPath`), so no release can read another's files.
- **Python.** Every `publish` command already takes `--data-root`, so it takes a historical release's root with no new option, and the gates expect that root's release: `identity_problems`, `manifest_identity_problems`, `release_index_problems` and `publish check`. A new root's first manifest is stamped with its own release (`load_manifest`), never the default. A historical release's flat views are its coverage, its measures not modelled and its OBR comparison, each with an exact header (`release_index.HISTORICAL_FLAT_VIEW_FILES`). Area provenance (`area_provenance.json`, bound by `flat_provenance_sha256`) is this Budget's: it ties each row of the results by area to its approved calculation, and a past event has no results by area. So `publish index` binds none for a past event, and `release_index_problems`, `scripts/check-public-files.mjs` and the page's `verifyReleaseIndex` refuse a past event's index or manifest that binds one. This Budget's provenance checks are unchanged. The dirty-tree check in `receipt.py` excuses each registered release root's `artifacts/` and `manifest.json`, and nothing else under `releases/`; without that, any write under a historical root would make every receipt unpublishable. `scripts/check_public_data.py` and `scripts/check-public-files.mjs` check every published release root, name a historical release in its problems (this Budget's read as before), and refuse any directory in `public/data/releases/` that the registry does not list.
- **Page.** `loadManifest`, `loadArtifact`, `loadPublication`, `loadDashboard`, `verifyReleaseIndex`, `loadVerifiedFlatCsv` and `loadVerifiedTable` take a `release`, this Budget's by default, and read only from that release's root (`dataRoot`). A loader handed a catalogue takes the catalogue's release, and refuses a release that differs from it. The route is `/budgets/[release]`, whose `generateStaticParams` lists the historical releases with `dynamicParams = false`, so an unknown id is a 404; `/budgets` lists the past events; `/` is the 2026 page, as now, and links to neither (question 2). Until past-event figures land, nothing outside the past events' own pages links to `/budgets`: no nav entry, intro link or static page (`src/budgetsUnlinked.test.js`). The check reads every source file and every page, script and SVG under `public/`. It finds an absolute route, a string that is a relative route (`"budgets"`, `"../budgets#list"`), and any URL a static page names, quoted or not, which it resolves against the page's address or its `<base href>` as a browser does.
- **The historical page** (`src/components/historical/HistoricalReleasePage.jsx`) loads the release's dashboard, then its three flat views (`src/utils/historical.js`). It reuses the 2026 charts, year slider and policy selector. The year slider takes an optional `years` prop, the event's own years, and offers them in place of the years a reader can choose (`SELECTABLE_YEARS`). The two decile charts' legends need no years: they list every selected measure, greyed out where it moves no household in the year shown (`legendMembership`). The decile charts take `pastEvent`, so their "More info" says only that a £0 measure changes no household shown. It never gives the reasons written for this Budget's measures: the employer NI relief's text says employers pay less, and `policyDetails` dates say when a measure is in force (`zeroReason`). Without these props each behaves as before, so the 2026 page is unchanged. The revenue chart takes no years, since its description names none. Each flat view is checked on its own and, when it fails, is shown as unavailable while the rest of the page still shows: its bytes must match the release index; the coverage must add up, as exact fractions (the classes partition the event's measures and the absolute value of its OBR costing, each share is its exact quotient, and the gap rows add up to the not-expressible class); and the not-modelled list together with the manifest's measures must account for every measure of the event, once.

### Importing a replay

```
uk-budget-data import-replay <policyengine-scorecard>/results/uk/dashboard_export/<variant>/*_20*.json [--data-root public/data]
```

This writes `src/uk_budget_data/events/<release>.json` for each event (`uk_budget_data.historical_events`). The registry is data, not code: an entry for each computed measure the rule can carry, and a not-modelled entry for every other measure, with its class and the scorecard's reason. With `--data-root`, it also writes the release's three flat views into its root. A measure's id is the scorecard's measure key, so every figure traces to its replay, and an id that is already a 2026 measure's is refused.

**The import rule.** Let the constructed world be the one the replay changed: the baseline of a reversal, or the reform of a forward delta. For each parameter path and replay year where the replay's two worlds hold different values, the entry sets the constructed world's value under that bare year, `{"Y": value}`. In years where the two worlds agree, the path is left at this dashboard's own current law. The values come from the export's `processed_parameter_values`: the value the replay checked its engine read at 1 January Y, in each world.

The rule copies the values the replay read, not the windows it submitted, because the replay reached those values by other routes on another engine. The scorecard's replay ran on policyengine-uk 2.130.1 and submitted each world in one of two ways (`pipeline/compute_uk_event.py`, `run_sim`). Most reforms went in as a reform dictionary when the simulation was built. That engine writes such a dictionary onto the statutory timeline and then processes the parameters as current law is, except for single-day or single-month keys and paths the statutory tree does not define, such as the generated `gov.economic_assumptions.indices.*` series: those override the already-annualised parameters (`policyengine_uk/utils/dated_reforms.py` at 2.130.1). A reform to the UC health element went through `Scenario.apply` on the built simulation instead, which overrides the annualised parameters (`uc_health_scenario`). The installed 2.132.6 reads a dictionary differently in two ways: a bare year on a calendar-year series names that calendar year rather than the fiscal year from 6 April, and a change to a generated series is written onto its timeline just after the step that generates it. This dashboard passes every imported entry, the UC health element's included, as `parameter_changes` (`historical_events.reform_for`), which the installed engine writes onto the statutory timeline. There, a bare-year key sets that fiscal year (that calendar year on a calendar-year series), so the value read at 1 January Y is the key's value. The parameter-level differential checks this on every imported measure. Copying the replay's windows as they are would not guarantee the same yearly values, since the routes and the readings differ. Copying the years where the worlds agree would impose the replay engine's current law on this dashboard's, which is pair drift and not part of the measure.

- **A reversal** becomes `baseline_parameter_changes`, with `parameter_changes={}`.
- **A forward delta** becomes `parameter_changes`, with `baseline_parameter_changes={}`. Both sides are explicit, so the 2026 configured baseline is never used.
- **UC health element.** The scorecard's `uc_health_element_refresh` route is built with `uc_health_element_change`, the template the 2026 measures use, which refuses a year outside the engine's UC rebalancing.
- **Validation.** Every path goes through the templates' own checks: a leaf in the installed tree, no UC health trap, and the data-limit and model-limit warnings, which decide the measure's status when it is generated. The scored-years rule (`uk_budget_data.scored_years`) runs at import.
- **Not imported.** A computed measure the rule cannot carry is listed as not modelled with the gap kind `dashboard_import` and its reason: another executor route, a sentinel value read as no limit, no change at all, a change in no scored year that the replay also costs at nothing, or a scored year an uprated amount would leave out. On the scorecard's newest pair (policyengine 6.9.0, policyengine-uk 2.130.1, policyengine-uk-data 1.58.1), all 25 computed measures import, and none is refused.
- **Provenance.** Each registry records the export file's digest, the scorecard registry's digest and the variant (packages, dataset, namespace manifest, receipt and comparison digests). The replay's yearly totals and intended values are kept beside each entry for the differentials.

### Generation and publication

A past event is generated from its own root, and that root decides everything else:

```
uk-budget-data generate --artifacts --artifacts-root public/data/releases/<id>/artifacts
```

With an artifacts root inside a historical release's root, `generate` reads that event's registry only (an id from another release or this Budget is refused), scores the registry's years (`--years` may only narrow them), and writes receipted artifacts only. It runs the event's measures in this process, one after another: `--jobs` other than 1 and `--backend modal` are refused, since a worker process is sent a measure that does not pickle by its id, which it looks up in this Budget's registry (`parallel.portable`). Then `publish reconcile`, `stage`, `approve` and `index` run with `--data-root public/data/releases/<id>`, exactly as for a 2026 measure, through the same receipts, data limits, model limits, integrity checks and release index. Question 1's rule replaces the Treasury reconciliation for a past event. The publish gates do not implement it yet: they reconcile every staged figure with Treasury inputs, and this writes none for a past event, so a past event is not staged until a past-event gate lands. An imported measure is built from its registry record alone, as parameter changes with no simulation modifier. So the pre-Budget baselines and the rail fares modifier in `reforms.py` never apply to it, and its id never matches `STUDENT_LOAN_REFORMS`. The policy years bound the years it is scored over (question 7). `ReformProcessor.process` computes the example households' income curves for every measure, so a past event's artifacts also carry curves for the 2026-27 example households. The past-event page does not show them (question 4).

## Tests

Each test is named for the property it holds. The fast-check and Hypothesis properties run over generated inputs, alongside the example tests.

- **The root decides the release** (`tests/test_historical_releases.py`, Hypothesis). For any path, with registered ids drawn as well as other names, a root inside `releases/` serves the registered release of that name or is refused; any other serves this Budget. Each release's root round-trips.
- **The route's release is the manifest's release** (`src/utils/publication/release.test.js`, fast-check; and in Python). For any release and any manifest identity, a manifest is accepted exactly when it names the requested release's id and date, and the loader fetches only that release's manifest URL.
- **No figure from another release's files.** For any release and selection, every request the loaders make is under that release's root, and this Budget's never enters `releases/`. For any two releases, files served at one are never shown on the other's page. An artifact path is accepted only when each segment is in the artifact writer's key alphabet, by the page and Python alike over one shared set of cases, so no encoded segment such as `%2e%2e` can lead a request into another root; every accepted path is requested exactly as checked (fast-check). A past event's root publishes end to end (stage, approve, index) with nothing written to this Budget's root. Both public-file checks refuse another release's identity, an unregistered directory, and a bound flat view with the wrong header or a row missing a field, and a test holds their headers equal to the page's.
- **Coverage partitions the event** (`tests/test_historical_events.py`). On every registry, the class rows' shares of the measures and of the absolute £ sum to exactly 1, as exact fractions; the gap-kind rows sum to the not-expressible row; and every measure is imported or listed as not modelled, once.
- **The import is faithful** (Hypothesis). For any replayed measure, the changes are exactly the constructed world's values in each path and year where the worlds differ; a reversal's go on the baseline and a forward delta's on the reform. Each stored entry is the rule applied to its stored replay values, and the registries regenerate byte for byte from the exports (`SCORECARD_DASHBOARD_EXPORT`), every registered event once.
- **Parameter-level differential.** For each of the 25 imported measures, the constructed side's scenario is built on the installed engine (no dataset), and each changed path is read at 1 January of each changed year. Every one equals the replay's intended value (relative tolerance 1e-9, as the replay's own check uses).
- **Generation reads only the release's registry.** A historical artifacts root generates that event's measures over its years, and refuses an id from another release or this Budget, a year outside its own, a flat-file run and an unregistered root; this Budget's generation keeps its registry and policy years.
- **National differential** (`uk_budget_data.historical_differential`, `tests/test_historical_differential.py`). For each imported measure and scored year, this dashboard's `budgetary_impact` value, read in pounds from the measure's receipted artifact, is set beside the scorecard's `measure_total_gbp`. They agree within `max(1%, £1m)` of the replay's figure. A figure the dashboard has not produced is reported missing, never zero. Until the scorecard has a replay on this dashboard's pair, it runs against the scorecard's newest pair. A difference can then come from the pair (model or data) or from the heads (`gov_balance` against the replay's declared heads). The report names both pairs and each measure's heads but does not attribute a difference to either, and it is informative, not gating, until the same-pair replay exists. The scorecard's replays on policyengine 6.10.x failed when the runner ran out of resources, and PolicyEngine/policyengine-scorecard#218 is the fix in flight. The tests hold the tolerance's properties (Hypothesis): it depends on the replay's size, not its sign, and a closer figure agrees whenever a farther one does. They also check that each measure-year is listed once, and that a figure is read only from an artifact whose receipt passes the publish gate's own check (`document_problems`), names the measure whose directory holds it, and is named by its digest, with rows for that measure and the receipt's years alone, and years the event scores. One measure's artifact under another's directory, a changed outputs digest, a changed table, another event's artifacts and this Budget's root are refused.
- **The page's checks hold** (`src/utils/historical.test.js`, fast-check). For any synthetic event, with each OBR row's class and gap drawn apart from its measure's, the coverage table built from it adds up, and its shares sum to exactly 1. Changing any share, any cell of a gap row, or the not-expressible class when it has gap rows makes it not add up. (Some changes cannot be seen from the table alone: one more measure in a class that holds all of them gives another event's consistent table.) The six registries' coverage adds up and accounts for every measure. Deleting the gap rows from a class that has measures, a computed row or value beyond the event's (both also on Autumn Budget 2024's own table), a share above one, a negative value, and a count the page cannot hold exactly are refused; a check that throws withholds its own view only. Shares display to the nearest tenth of a percent, and a non-zero share never reads as zero.
- **The page shows a past event's own files** (`src/components/historical/HistoricalReleasePage.test.jsx`). On a release served from the publication fixture (synthetic data), the page names its pair, fetches only under its root, and shows the coverage, the measures not modelled and the OBR comparison. The coverage says how many measures the scorecard's replay computed apart from how many of the page's own measures have figures, since a computed measure can be held, not computable or unavailable here, and it adds its counts exactly, past 2^53. Another release's manifest at its root shows nothing; changed flat-view bytes withhold that view only; a bound coverage table that does not add up, and a not-modelled list that leaves out or double-counts a measure, are withheld. The routes are one static page per past event and an index, newest first.
- **The 2026 page is unchanged.** No existing test is modified (the shared `World` helper only gains an optional release, whose default is this Budget's root), and the full suite passes on CI, as it does on #104's head.
