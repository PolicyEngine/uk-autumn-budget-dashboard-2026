# Budget-day checklist (one page)

The order of the day on one page. Every step's detail, and every reason, is in [`budget-day-runbook.md`](budget-day-runbook.md); where the two differ, the runbook wins and this page is wrong. Times are UTC (UK time equals UTC from 25 October). Roles as in the runbook, where #247 (27 October, 11:19Z) set them: **Integrator** generates, stages, approves, writes the review rows, opens the PRs and merges; **Reconciler** steps are entering the Treasury costings and running the reconciliation, done by agents and checked by the Integrator, so where a row below gives the Reconciler an approval or the review rows, the Integrator signs them; **second signer** (with one other person) signs every hand-written modifier's attestation. Names go in the clock table, not here. Agents follow [`budget-day-agents.md`](budget-day-agents.md); every signature, who signs it and what they check first, is in [`budget-day-people.md`](budget-day-people.md); the day at a glance, and how data reaches the dashboard, is in [`budget-day-map.md`](budget-day-map.md).

Every Modal command starts `uv run --with modal==1.6.2 python -m uk_budget_data.cli`, written `MODAL` below. The `uk-budget-data` script form fails with `--with modal` (it runs the project's own Python, which has no `modal`). Commands without Modal stay `uv run uk-budget-data ...`. In zsh or bash, `MODAL() { uv run --with modal==1.6.2 python -m uk_budget_data.cli "$@"; }` makes the commands below paste as written: a variable holding the command with its spaces wouldn't split in zsh.

## Never

1. **Never put two measures in one call (one call per measure since Vahid's decision of 27 October), and never run `--artifacts` without `--reforms`** (that runs every measure, hand-written ones included). Each run of a hand-written modifier writes a new artifact that needs its own two-person attestation; on 26 October this left two artifacts for each. If it happens, attest and stage one of them; `review-rows` then deletes the other.
2. **Never run `publish review-rows` while a `generate` is running**, or before every artifact you want is staged: it deletes unstaged artifact directories.
3. **Never interrupt a Modal run that has gone quiet.** Results come back in measure order, so one slow container holds back the rest (up to the 45-minute timeout). Ctrl-C loses everything not yet written.
4. **Never mix local and Modal artifacts in one release** without deciding to: staging then needs `--adopt-execution`, which makes every other entry stale.

## If a Modal container fails

The command prints `<id>: FAILED in its Modal container: <error>` in its place, writes every other artifact, starts no combined run in that call, ends with `FAILED <id>` lines (apart from `REFUSED` ones) and the rerun steps, and exits 1. Then:
1. Stage the written ones as they are.
2. Rerun only the printed ids: `MODAL generate --artifacts --backend modal --reforms <one id>`, one call each, and stage them.
3. Then the combined run with the printed member ids.

A **refusal** is not a failure: a gate refused the measure (a data limit, a scored year, a thin decile cell once #208 is in) and a rerun gives the same answer. Fix the measure or leave it out.
