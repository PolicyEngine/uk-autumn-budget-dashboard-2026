# Forecast vintages inputs

The Forecast vintages tab reads `public/data/obr_forecast_vintages.json`. `uk-budget-data forecast-vintages` writes it from the files here (`src/uk_budget_data/forecast_vintages/`), and sets its row in `data_inputs/public_data_review.csv` to pending. It holds no PolicyEngine figures: every value is the OBR's or the ONS's.

```bash
uv run uk-budget-data forecast-vintages --fetch   # refresh ONS and house prices, then build
uv run uk-budget-data forecast-vintages           # build from the files committed here
```

## OBR files

obr.uk refuses scripted downloads (`docs/budget-day-runbook.md`), so these come from Internet Archive captures of their obr.uk addresses, read through the archive's `id_` route, which returns the captured bytes unaltered. They are committed unedited. The build refuses any whose SHA-256 differs from the one pinned in `sources.py` (and listed here). `--fetch` downloads one only if it is missing, and keeps it only if the bytes match. It requests only web.archive.org, www.ons.gov.uk and landregistry.data.gov.uk (`fetch.SOURCE_HOSTS`), redirects included, so obr.uk itself is never requested, however its host is written.

## Checks

Each variable's outturn is set against the database's own outturn row (outturn as available at the March 2026 forecast) over the last eight periods both have, and the build stops if they differ by more than the variable's tolerance (in `variables.py`): a percentage point for growth rates, rates and shares of GDP; 2 per cent for employment; 2.5 per cent for nominal GDP, receipts and spending; 5 per cent for borrowing; £5 billion for the current budget. A tolerance is a share of the value only for a forecast of levels, whose gaps are in the value's own units. The largest gap for each variable, and the periods compared, are in the published file (`check`), and the gap as written (to four decimals) must be within the tolerance as written, as the page states both (`check_as_read` in `build.py`; the page's loader applies the same rule, and `tests/fixtures/forecast_vintages_check_cases.json` holds both to the same cases). Every measure has a check: the page refuses a file with a measure without one. Quarterly income per head, the one index, is set against the March 2026 Table 1.5 to its launch quarter (the build sets no index against a database sheet): its tolerance is 1.5 percentage points of growth on a year earlier, since Table 1.5 divides households' and non-profit institutions' income (NRJR) by the whole population (EBAQ), while CRXX is households' income alone, per head.

Each forecast's values must run from its launch period (or, but for the index, the period after) without gaps, over two periods or more. Each forecast's figure for its launch period, an estimate of a period already over when it was published, must read as its measure's kind against today's outturn: a level within half the outturn's largest size of it, a growth rate within 10 percentage points of the outturn's rate, and an index's ratio to the outturn within 1.5 times of every other forecast's. Every growth rate is under 100% either way, every index is above zero, and at least one forecast's launch figure of each measure is set against the outturn (the outturn has that period, and for a growth rate the one a year before). The figures after the launch are forecasts and are never set against the outturn (`check_kind` in `build.py`; the page's loader applies the same rule, and `tests/fixtures/forecast_vintages_kind_cases.json` holds both to the same cases). No forecast after March 2026 is taken.

## The published file

`public/data/obr_forecast_vintages.json`:

- `meta`: `newest_vintage` (March 2026); `parliament`, the start and end periods the page labels, by frequency; `launch_rules`; `left_out`, the database's variables the tab does not show and why; `gaps`; `sources`, every OBR file (address, Internet Archive capture, SHA-256), ONS series (page, release date, time of download, SHA-256) and the House Price Index.
- `variables`: one per variable, in the order of `variables.py`, each with `id`, `label`, `group`, `frequency` (`calendar`, `fiscal` or `quarterly`), `units` (the unit pills it offers: `level`, `index`, `pct`, each saying which measure it reads; a quarterly measure's `level` is always `annualise`d, a quarter's figure ×4 under an axis that names a year, and no other unit is), `default_unit`, `notes`, and the measures `level` and `share` (`null` where there is no share of GDP). A measure has:
  - `unit`, `kind` (`growth`: the forecasts are percentage changes on a year earlier; `index`: the forecasts are an index whose ratios carry the outturn on; `level`: the forecasts are in the outturn's units), `decimals`;
  - `outturn`: `{period: value}`, in `unit`;
  - `vintages`: each forecast's `id`, `label`, `year`, `month`, `launch` (its last period of outturn) and `values` (`{period: value}` from its launch on, as the OBR published them);
  - `outturn_source`, `forecast_source` and `check` (the outturn set against the OBR's own).

Periods are `"2024"`, `"2024-25"` or `"2024Q2"`. A period with no value is absent, never zero.
